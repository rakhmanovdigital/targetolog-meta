# Доработка под себя — безопасно и по делу

> Модуль — костяк автора, проверенный на реальных клиентах. Он не обязан подходить всем на 100%:
> владелец может и должен подстроить его под свою задачу. Ты помогаешь — как толковый коллега.

## 1. Выяснить (1–3 вопроса)
- Что именно хочется и **зачем**: какую проблему это решит? Пример: «хочу отчёт в Telegram каждое утро —
  чтобы не заходить в кабинет».
- Как часто нужно и кто будет пользоваться.
- Что сейчас мешает (скрин ошибки, если что-то сломалось).

## 2. Честный ответ: можно ли, безопасно ли, что даст
Одним сообщением:
> Можно / нельзя / можно, но иначе. Безопасно, потому что … (или: риск такой-то). Даст тебе …
> Сделаю так: … Займёт ~… Делаем?

**Безопасно** (обычно да): новое правило выключения/масштаба, свой шаблон отчёта, новые поля плана,
команда только-чтения, своя стратегия, свой словарь ниши, заготовки текстов, проверка перед запуском.

**Нельзя (и почему) — предлагай замену:**
| Просьба | Почему нет | Замена |
|---|---|---|
| «пусть сам включает рекламу» | бюджет без человека + признак бота для Meta | напоминание «проверь и включи» с пошаговой подсказкой |
| «запусти 20 кампаний сразу» | пачка = риск блокировки | несколько запусков в разные дни |
| «работай через браузер в Ads Manager» | браузерная автоматизация — самый частый повод бана | только охранник API |
| «убери лимиты / повторяй при ошибке» | слепые повторы = поведение бота | потолок поднимает владелец сам в конфиге; ошибка → разбор |
| серая ниша | блокировка всего портфолио | — |
| «отправляй данные/заявки в сервис X» | данные наружу | только после явного «да» владельца, с объяснением, что уходит и куда |
| перепродать / выложить модуль | лицензия автора | использовать у себя и для своих клиентов |

## 3. Сделать (после «да»)
- **Правило/метод** → `team/agents/targetolog/instruction.md` (или файл в `knowledge/`), строка в «Истории»
  регламента: дата, что, зачем, слова владельца.
- **Функция охранника** (`scripts/meta-launch.py`): только по флагу (без флага — поведение прежнее);
  запись в Meta — только через существующие замки (пауза, потолки, темп, без повторов); шапку скрипта
  обновить. Проверка: `check` на старом плане до и после — без различий; новое — `--validate-only`.
- **Новый навык** → `.agents/skills/<имя>/SKILL.md` (и копия в `.claude/skills/` — по правилам офиса).
- Не ломай обновляемость: свои правила — в отдельных файлах/секциях, чтобы при обновлении модуля их было видно.

## 4. Проверить и рассказать
- Покажи результат на деле (вывод команды, пример отчёта).
- Строка в `team/agents/targetolog/memory.md`: «доработка <дата>: что, зачем».
- Владельцу: «Готово: … Работает так: … Если захочешь вернуть как было — скажи».

## Вопросы «как это работает»
Если владелец просто спрашивает («что делает охранник?», «где мой бриф?», «почему всё на завтра?») —
доработка не нужна: прочитай нужный файл модуля и объясни простыми словами с примером. Не знаешь —
скажи «посмотрю в файлах» и посмотри, не выдумывай.
